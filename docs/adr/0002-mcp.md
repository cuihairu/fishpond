# ADR-0002：MCP Server 面采用 rmcp 3.11

**日期**：2026-11-25
**状态**：Accepted（F009M，用户令「fishpond 需要补上一个 mcp 功能」）
**关联**：实施文档 §13（对外契约 = REST `/api/v1` + OpenAPI）；MCP 为 REST 之外的第二个对外协议面，本文记录其实现选型。

## 背景

- 实施文档全文未定义 MCP；MCP 面由用户直接下令补充，服务对象是 coding agent（Claude Code 等）。
- 定位约束：不新增业务逻辑，工具 = REST 语义的 1:1 包装；权限/scope/租户判定复用 server 鉴权层；Mock 是唯一 CI 目标（§7.3）。
- 需要双 transport：stdio（agent 拉起子进程）与 streamable HTTP（`POST /mcp`）。

## 决策对比

| 维度 | rmcp 3.11（official Rust SDK） | 手写 JSON-RPC |
|---|---|---|
| 协议版本协商 | 内置（initialize 握手、版本选择） | 需自实现，易漂 spec |
| 工具 schema 生成 | `#[tool]` 宏 + schemars 自动生成 inputSchema | 手写 JSON Schema + 手动校验 |
| stdio transport | `transport-io` 开箱即用 | 自实现行分帧 JSON-RPC codec |
| streamable HTTP | `transport-streamable-http-server`（会话管理、SSE 流） | 需自实现会话、SSE、重连语义，工作量最大 |
| 测试基建 | in-memory transport（`tokio::io::duplex`）可做全链路 JSON-RPC 测试 | 需自造测试 transport |
| 维护方 | modelcontextprotocol 官方仓（rust-sdk） | 本仓自担 |
| MSRV | **rust-version = 1.88，与 §8 基线完全一致** | 无（但自担实现成本） |
| 依赖面 | serde/tokio/http 系（本就已进入依赖树） | 零第三方（但代码量大） |

## 结论

采用 **rmcp 3.11.0**（features：`server`、`macros`、`schemars`、`transport-io`、`transport-streamable-http-server[-session]`；测试侧另开 `client`、`transport-async-rw`）。MSRV 与 workspace `rust-version = 1.88` 对齐，§8 基线不动。手写方案的唯一优势（零依赖）不抵协议面自实现的长期维护成本与偏差风险。

## 附带决策

1. **鉴权接缝（M0）**：`FISHPOND_API_KEY`（stdio）/ `x-fishpond-api-key` 或 `Authorization: Bearer`（http）→ `ApiKeyStore` 解析为 `{tenant, scopes}`。M0 用 CLI bootstrap + Mock 种子键；F007/F025 落地后替换为持久化 key store，`AuthContext` 形状不变。
2. **subscribe_events 降级为快照**（M0）：live push 依赖 F017 事件管线，未落地前 `subscribe_events` 返回近期事件快照，M1 桥接为 MCP notification。
3. **错误码**：未认证/越权用 JSON-RPC `INVALID_REQUEST`（-32600）+ 明确 message；资源不存在用 `RESOURCE_NOT_FOUND`（-32002）；参数错误用 `INVALID_PARAMS`（-32602）。不自定义码，避免客户端兼容面扩大。
4. **结构钉**：`scripts/check_workspace.py` 新增规则——`fishpond-mcp` 内部依赖只允许 `fishpond-domain / fishpond-storage / fishpond-server`（禁 worker/browser/provider 实现），MCP 工具不得绕过 provider-sdk 抽象直连上游。
5. OpenAPI（REST 契约）不变；MCP 工具描述承担 agent 可发现性。
